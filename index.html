Development

Checklist voor development-taken. Source: alka-group-agentic-engineering/development ↗

1

Before You Start

Voordat je begint
→
Lees de bestaande code — Zoek in de codebase voordat je nieuwe code schrijft. Bestaande functies hergebruiken, niet opnieuw maken.
→
Houd de taak klein — Één feature per keer. Kleine commits, kleine diffs. Niet alles tegelijk refactoren.
→
Geef broncode als context — Als je een package/framework gebruikt, raadpleeg de broncode. Niet raden — zoek het zelf op.
→
Test lokaal — Test voordat je pusht. Check op console errors. Verifieer op mobiel en desktop.
→
Beschrijvende commit messages — Wat is er gedaan en waarom. Niet "update" of "fix" — wees specifiek.

Gates: bestaande code doorzocht · taak is klein genoeg · broncode geraadpleegd · lokaal getest · commit message is beschrijvend

2

Code Structure Cleanup

Na werkende feature

AI agents nemen vaak de makkelijkste weg: nieuwe functies maken in plaats van bestaande te hergebruiken. Een feature kan werken terwijl er nog steeds duplicatie in zit.

→
Inspecteer bewerkte bestanden — Bekijk welke bestanden door de feature zijn aangeraakt.
→
Identificeer herhaalde logica — Gedupliceerde runtime mechanics, herhaalde API calls, parsing, validatie, business logic.
→
Service-layer extractie — Beweeg herhaalde mechanics naar herbruikbare service-layer functies/modules.
→
Implementeer & test — Houd de diff klein. Verander geen user-facing behavior. Draai tests/typechecks.

Gates: behavior unchanged · duplicatie verminderd · aanroepen simpeler · tests gepasseerd · diff gefocused

⚠ Valkuilen

Hele app refactoren · Alles hernoemen · Cleanup mengen met nieuwe feature · Alleen formatteren

3

Grep Loop Review

Vóór push

Een automatische review loop: maak kleine PR → laat reviewen → voer feedback terug → herhaal tot schoon.

→
Pre-Flight Check — Is de PR te groot? Splits hem eerst.
→
Review-Fix Loop — Lees diff → lees feedback → fix alleen relevante issues → voeg tests toe → draai tests → commit → herhaal.
→
Stop-conditie — Stop als PR schoon is of als een menselijke beslissing nodig is.

Gates: PR klein genoeg · diff gelezen · alleen relevante fixes · tests gepasseerd · samenvatting items

⚠ Valkuilen

Enorme PRs · Geen tests · Blind elk comment accepteren · Geen stop-conditie

4

Security Checklist

Altijd vóór push
Code
  • ☐ Geen hardcoded API keys of secrets
  • ☐ Geen console.log met gevoelige data
  • ☐ Input validatie op alle user input
  • ☐ Error handling op alle async operaties
  • ☐ Geen eval() of innerHTML met user input
Dependencies
  • ☐ Geen packages jonger dan 14 dagen
  • ☐ Geen onbekende of ongebruikte packages
  • ☐ package-lock.json gecommit
GitHub
  • ☐ Geen .env files gepusht
  • ☐ Geen gevoelige data in commit messages
  • ☐ Branch up-to-date met main vóór merge
Deploy
  • ☐ Lokaal getest op mobiel en desktop
  • ☐ Geen console errors in browser
  • ☐ Formulieren werken (indien van toepassing)
  • ☐ SSL certificaat geldig (voor websites)

⚠ Bij twijfel: stop en vraag de CTO voordat je pusht.

5

Launch

Ship it

Niet eeuwig verstoppen achter "nog één feature". Een semi-functioneel MVP met feedback verslaat een perfect privé project.

🚀 Launch eerder dan je je comfortabel voelt
